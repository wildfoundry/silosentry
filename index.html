SiloSentry

Imagine a SaaS IoT company that puts temperature and moisture sensors in grain bins, then has to support those Linux boxes for years in the field. This site uses that story to show what Dataplicity is for.

How it’s wired See the fleet

SiloSentry isn’t a product we’re selling. It’s a made-up but believable OEM: edge gateways on elevators, a cloud app for the grain data, and Dataplicity underneath for remote access, monitoring, and ops — so you can see the platform in a concrete setting.

The setup

Grain sensors on the edge. SaaS in the cloud. Dataplicity in between.

Enough product to make the ops story make sense: Linux gateways at co-op elevators, a customer-facing cloud for bin telemetry, and Dataplicity as the control plane that keeps devices reachable without VPNs or inbound ports.

Dataplicity

control plane

Provision, presence, Wormhole, terminal, alerts, status, OEM tooling. The ops substrate.

Fleet

Ship a gateway. It shows up in Dataplicity.

Install is a one-liner at first boot. Sites become Networks. SKUs become device classes. Support opens a co-op’s network when they call — no public IP required.

  1. Provision curl … | sudo bash with an org key. Outbound only.
  2. Group by site Each elevator is a Network; tags carry customer and criticality.
  3. Operate the fleet Online/offline, device detail, and bulk actions live on the same record.

Remote access

Open the gateway’s local UI. Drop to a shell when it wedges.

Edge boxes usually host a small admin page on localhost. Wormhole publishes that over HTTPS. When the process is stuck, terminal is break-glass — still without a truck roll.

Ops

Know when a bin gateway goes quiet — before harvest calls pile up.

Alerts, status pages, file requests from installers, and a map when LTE flakes regionally. Same patterns any SaaS IoT fleet needs; the grain story just makes them concrete.

In practice

What a support day looks like.

Morning

Hot spot on a bin

Alert → Wormhole into the gateway UI → terminal if the service is wedged → close it out.

Midday

Gateway offline

Connectivity alert → map / SIM check → field tech uploads a photo via file request → back online.

Afternoon

Pre-harvest sweep

Filter critical sites, confirm health checks, spot-check a shell on a couple of gateways.

Later

Ship more hardware

Licences and claim codes travel with the boxes; Dataplicity stays the support plane.

Takeaway

The grain story is disposable. The ops map isn’t.

Swap bins for chargers, cameras, or cold-chain nodes — the Dataplicity loop stays the same.

Class = SKU → Network = site → Wormhole = local UI → Terminal = break-glass → Alerts/Status = trust → Licences/RMA = commercial scale.

Explore Dataplicity if you’re shipping Linux devices that still need a support loop after they leave the factory.
